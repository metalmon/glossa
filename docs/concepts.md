# Concepts

The mental model behind glossa, in one page. Each section links to the doc that goes deeper.

## Corpus

A **corpus** is a folder of source documents (PDF, Office, Markdown, text, …) on disk. glossa is
**file-first**: your files are always the source of truth. Everything glossa derives from them —
the search index, the reasoning graph — is a disposable overlay that can be rebuilt at any time by
re-indexing. See [architecture.md](architecture.md).

## The `.glossa/` state directory

The first `kb index` (or MCP `ensure_fresh`) creates a `.glossa/` directory holding all derived
state:

| Path | Contents |
|------|----------|
| `index/` | Tantivy BM25 full-text index |
| `graph.sqlite` | The knowledge graph (structural + reasoning + derived layers) |
| `manifest.json` | File-change tracking for incremental indexing |
| `ontology.toml` | Optional domain overlay constraining the reasoning graph (see below) |
| `notes/` | Agent notebook — free-form and `.csp` limit-table notes, kept out of the corpus walk |
| `traces/` | Per-call MCP trace logs, when the server is started with `--trace` |
| lock files | Cooperative cross-process locks (`index.lock`, `generalize.lock`, `notebook.lock`, …) |

`.glossa/` is **rebuildable**: deleting it loses only derived state, never source documents;
re-indexing regenerates the index and structural graph from the files (the reasoning layer, being
agent-authored, is not regenerated by a plain re-index — see
[graph-lifecycle.md](graph-lifecycle.md)).

By default `.glossa/` is co-located with the corpus (`<corpus>/.glossa/`). Point it elsewhere with
`--state-dir` (env `GLOSSA_STATE_DIR`) — most commonly so state lives on local disk while the
corpus itself sits on a network mount (file locks and journaling are unreliable over SMB/NFS; see
[troubleshooting.md](troubleshooting.md)).

## Roots and labels

A corpus can be more than one folder. `--root [LABEL=]PATH` is repeatable:

```bash
kb mcp --root docs=/mnt/store/docs --root specs=/mnt/store/specs --state-dir /var/lib/glossa/role
```

A bare `--root PATH` (no `LABEL=`) auto-labels from the path's basename. The same list can come
from the `GLOSSA_ROOTS` environment variable, one `[LABEL=]PATH` per line (blank lines skipped) —
useful for a service unit's `EnvironmentFile`. A single positional `PATH` (no `--root` at all) is
the simplest case: one corpus, the empty label. When any `--root` flag is given, it wins outright
over `GLOSSA_ROOTS` (they are never merged). Every document's key is `<label>/<relpath>`
(empty-label roots just use `<relpath>`).

**Why**: serve several document folders from one MCP process, and keep `.glossa/` on local disk
while one or more roots live on a network share. Full flag/env reference:
[cli-reference.md](cli-reference.md), [configuration.md](configuration.md).

## Search index vs knowledge graph

glossa maintains two different structures over the same corpus:

- **Search index** — Tantivy BM25 full-text index. Powers `search` (ranked keyword lookup) and
  `grep` (regex/literal over extracted text). No graph, no reasoning — just ranked or exact text
  matching.
- **Knowledge graph** — a SQLite-backed reasoning graph (`graph.sqlite`) with three layers:
  - **Structural** (automatic) — `Document`/`Section` nodes and `CONTAINS`/`MENTIONS`/`NEXT`/`PREV`
    edges, built during indexing.
  - **Reasoning** (agent-authored) — domain nodes (e.g. `Symptom` → `Cause` → `Resolution`) and
    typed edges an agent or the `kbx` pipeline writes via `graph_upsert`, validated against the
    ontology.
  - **Derived** (`graph generalize`) — transitive closure, `SIMILAR` links, communities and
    centrality, computed deterministically from the two layers above.

Details: [architecture.md](architecture.md), [graph-and-ontology.md](graph-and-ontology.md).

## Ontology presets

An **ontology** (`.glossa/ontology.toml`) declares which reasoning node/edge types are valid for a
corpus, and which of them require grounding to a source section. glossa ships baked domain
**presets** (`kb ontology list`) so most users never hand-write one — `kb index ./my-corpus
--ontology support` materializes a preset and indexes in one step. Once `.glossa/ontology.toml`
exists on disk, it is the single source of truth — hand-edit it freely from then on. See
[ontology-presets.md](ontology-presets.md).

## Profiles (reader / editor / full)

An MCP server's **profile** controls which tools are advertised to the connecting agent — it is
**not** an access-control mechanism (every profile still serves fresh data; the underlying corpus
and graph are the same). `kb mcp`'s own default is `--profile editor`; the platform service
scripts (Ansible/PowerShell/launchd) default to `reader`. `reader` hides write/admin tools (index,
graph writes, `purge`, `note`/`del`) and the low-level graph-navigation tools; `editor` adds all of
those except `purge`; `full` adds `purge`. See [mcp.md](mcp.md) for the complete per-tool table.

## Scope

Several tools (`search`, `grep`, `graph glossary`, `graph near`, `graph reach`, and their MCP
equivalents) take a `--scope`/`scope` argument restricting results to one document or a path-glob
(e.g. `manual.pdf` or `guides/**`). Scope is **ANDed** with `--glob`/`-g` when both are given —
scope narrows to a document or subtree, glob narrows by filename pattern within that.
